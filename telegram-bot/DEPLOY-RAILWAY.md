# 🚂 نشر البوت على Railway (24/7) — دليل وخطوات حرجة

> ⚠️ **مهم جداً قبل النشر/بعد كل تحديث:** اقرأ قسم «الإعدادات الحرجة» أدناه،
> وإلا ستُفقد بيانات المشتركين وملف `.env`.

---

## 1) المتغيّرات (Variables) — إلزامية على Railway

ملف `.env` **لا يُرفع على GitHub** (وهذا صحيح أمنياً)، لذلك لا يوجد تلقائياً على Railway.
يجب إضافته يدوياً من لوحة Railway:

**Service `al-mohandes` → تبويب Variables → + New Variable**، وأضف:

| الاسم | القيمة |
|------|--------|
| `BOT_TOKEN` | التوكن الكامل من `@BotFather` |
| `ADMIN_IDS` | `5555912861` |
| `APP_NAME` | `المهندس` |
| `IOS_URL` | `https://al-mohandes-app-2026.vercel.app` |

> الكود يقرأ متغيّرات البيئة أولاً (قبل ملف `.env`)، لذا هذا يكفي لعمل البوت.
> بدون `BOT_TOKEN` سيتوقّف البوت فوراً عند الإقلاع.

---

## 2) Volume (قرص دائم) — لحماية بياناتك 🔴

قرص Railway **مؤقت (ephemeral)**: كل إعادة نشر (Deploy) أو إعادة تشغيل تَمسح
مجلد `data/` → تفقد **المشتركين + الإعدادات + النسخة الحالية**.

**الحل الإلزامي — أنشئ Volume:**

1. من اللوحة: **`+ Add` → Volume** (أو Service → Settings → Volumes).
2. **Mount Path** = `/app/data`
3. أعد النشر (Redeploy).

> لأن الحاوية تستخدم `WORKDIR /app` (انظر `Dockerfile`)، فمسار البيانات داخلها هو `/app/data`.
> بهذا تبقى كل البيانات محفوظة حتى مع التحديثات.

> **ملاحظة APK:** ملف `releases/current.apk` أيضاً يُفقد عند إعادة النشر لأنه غير داخل الـ Volume.
> للملفات الكبيرة أو البقاء دائماً، استخدم **خيار الرابط المباشر** عند رفع النسخة (يسحبه البوت عند الطلب)،
> أو ارفع الـ APK على تخزين سحابي وضع رابطه في `DOWNLOAD_URL`.

## 4) التحقق بعد النشر

1. **Deploy Logs:** يجب أن ترى `🤖 بوت المهندس يعمل الآن (long polling)...` و`✅ تم تطبيق وصف البوت.`
2. افتح [@Almohanndesbot](https://t.me/Almohanndesbot) وأرسل `/start` ثم `/panel`.
3. `/stats` للتأكد من عدّاد المشتركين.

---

## 5) تحديث الكود لاحقاً

على جهازك المحلي:
```powershell
git add telegram-bot/*.mjs
git commit -m "تحديث البوت"
git push
```
Railway يعيد النشر تلقائياً من GitHub. **المتغيّرات والـ Volume يبقيان كما هما.**
